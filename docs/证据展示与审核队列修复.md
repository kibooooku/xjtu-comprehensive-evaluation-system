# 证据展示与审核队列修复（2026-10-26）

## 证据优先展示

对照核对及完整详情均按“本人参与证明 → 有效性证据 → 原件”展示。学生、学生审查员和辅导员共用该顺序。尚无截图时占位也在原件前，后台识别完成或手工保存只更新独立证据容器，不再把证据追加到几十页原件之后，也不重建原图、表单或框选画布。

模型的长篇分析说明不再展示，包含自动填表后的蓝底解释、后台建议中的解释段落及完整详情中的分析说明。活动名称、计分、应用建议入口和简短核对提醒保留；不删除数据库中的原始分析记录，不改变审核依据或学生修改权限。

## 学号定位

正式记录只读核查确认：夜跑第22页、绕绳第8页都已有准确的学号文字及字级坐标。旧代码先移除空格，使前面的班号与学号粘连，随后数字边界检查将其排除，参与图因此只标注了姓名或班级。

修复保留原始字段边界，使用同一个精确匹配位置映射字框，支持全角数字和可靠的字间空白。不会用相似号码替代真实学号，也不会跨行、跨列拼出编号。长号码中的子串及与相邻数字紧连的片段不能作为账户学号。截图仍为原页整宽、四分之一页高，并优先围绕学号生成单张参与证明。

新自动建议的红框变化可更新当前可编辑的旧自动截图，不因同页、同范围去重而保留旧框；手工编辑和已冻结证据不覆盖。公示数字遮罩同步补充短片段编号的保护，无法可靠定位或已有遮罩不足时拒绝返回公示图，私人审核图与冻结记录保持原状。

真实样本使用已有识别缓存离线验证，两份新建议均包含学号红框，未调用OCR或AI，未修改正式数据库。包含个人信息的预览及诊断留在被Git忽略的 `instance/` 目录。

这两个现有条目核查时均已提交待学生初审，证据已经冻结。因此不直接更换当前审核快照；学生撤回后，在可编辑工作稿中重新识别可生成新红框。

## 辅导员待审队列

当前班级的7项待审均处于学生初审，待辅导员审核为0。按既定需求，集体活动、理论学习、社会服务和学生组织任职可在学生初审通过后直接通过；需认定活动资格的科研、文体竞赛和奖励类，才进入辅导员阶段。原队列权限过滤符合该流程，但工作台将两个阶段合计为“待审核”，导致入口与列表看似不一致。

工作台现分开显示待学生初审、待辅导员审核。辅导员待审页显示两个阶段的数量、空队列原因和“查看班级申报”入口；辅导员可查看初审进度，但不能跳过初审直接审批。统计和查询沿用班级与学年的RBAC范围。
