# 七大类自动计分与状态一致性验收

## 统一流程

七大类均执行“原件文字与位置 → 本人记录与共同背景 → 规则计算 → 建议应用 → 当前稿与表格 → 提交校验”，不直接接受模型给出的分值。规则版本为 `xjtu-2018-evidence-v2`，分析版本为 `moral-score-v4-scoring-state`。学生仍可手动填写任何符合基础数字格式的分值，并确认0分，无需填写理由；审核资格和年度汇总规则保留。

本人字段只取本人行或单人证明。校级、省级等共同背景来自对应活动正文；同一小项的补充证明须有可对应的活动名称及明确名单/附件关系，不能借学校标志或另一个活动的等级。检查过的空间位置关系不能再用原始OCR乱序文本拼接绕过。

## 七类正常案例与边界

| 大类 | 实际链路中的虚构案例 | 应填分值 | 重点边界 |
| --- | --- | ---: | --- |
| 集体活动 | 本人明确参加2次集体活动 | 0.60 | 次数取证明；不能用模型虚构的次数；突出贡献交人工认定 |
| 思想政治理论学习 | 本人参加普通党团理论培训1次 | 1.00 | 省部级、优秀学员分别取证；未参加、未获优秀不能正向加分 |
| 社会服务 | 本人有效志愿工时16小时 | 0.50 | 工时仅取本人；负数不截成正数；年度志愿子项上限1分 |
| 学术科研及创新创业 | 本人省级二等奖 | 6.00 | 级别、奖次、成果类型独立；论文需本人排序和第一署名单位 |
| 文体竞赛 | 本人校级文体三等奖 | 1.00 | 奖次制保留THIRD，名次制保留PLACE_n，不能把三等奖改成第3名 |
| 学生组织社团任职 | 班长满12月，考评良好 | 1.50 | 本人岗位、任期、考评须对应；不足一年人工核定；不合格合法0分 |
| 奖励分 | 本人获校级精神文明先进个人表彰 | 2.00 | 荣誉不要求必须另有一二三等奖；不能拿别人的表彰或组织级别计分 |

体育证明采用一、二、三等奖表达时，按同赛事级别的前三档提供奖次制填报建议（PRIZE_BAND），不据此推断获奖人的精确名次。资格仍按原流程审核。该口径与体育第4—8名、破纪录等规则分别处理；不再因已经明确的三等奖不属于PLACE_3而保留默认0分。原办法没有独立固定金额的专利指向、项目结项和不足年任职等，必须具体说明人工核定原因。

## 分值状态

API的 `score_resolution` 在当前稿、列表和建议中提供：

- `RULE_APPLIED`：有明确规则计算结果，`value`为两位分值，允许真实0。
- `NEEDS_REVIEW`：缺依据或有冲突，`value=null`；保留稿值只放在 `retained_value`，页面展示“待核定分值”及具体缺项。
- `MANUAL`：学生手动填写/确认，或已冻结分值，正常显示0或非零数，不被新建议覆盖。
- `UNANALYZED`：尚未形成分值；默认数据库0不是已完成计分。

`missing_facts`为 `{code,label}` 数组。页面不把AI调用成功当作填分成功，后台显示“条目已提取，分值待核定”。单项/批量提交均拒绝未核定自动分值；批量混选仅提交已核定项，未决项保留草稿和勾选。

PUT显式 `score_confirmed:true` 与当前 `requested_score` 可确认人工0，无需理由。只改标题、仅保存无意义空字段不会确认0或误标手改。学生实际改过分值的原审查提示继续使用 `student_modified_score`，同值确认0以独立标记表示。应用未决建议只更新信息，不清除有效的人工0确认。

保存和确认使用表单加载时的 `expected_version`。后台更新了标题、分值、字段或附件时，脏表单不推进版本；旧页返回409并保留用户输入。纯状态或证据刷新、表单依据完全相同时才安全推进版本。材料或计分字段变化后，旧自动分值进入待核定；已手填或冻结分值保持保护。

## 可重复验证

1. `tests/test_all_category_scoring_contract.py`：真实位置文字、真实本人关联、分析、应用、详情与分组列表，覆盖七类正常/缺身份、真实0、人工/冻结及非法次数。模型故意给99，期望规则替换或明确未决。
2. `tests/test_score_resolution.py`：真0与未决分开、人工确认0、默认0提交门禁、部分建议保留人工0、并发旧版本保护。
3. `scripts/browser-scoring-contract-smoke.mjs`：[模拟界面报告](screenshots-v2/browser-scoring-contract-mock.json)，[虚构界面](screenshots-v2/19-scoring-resolution-contract-mock.png)。
4. `node scripts/browser-scoring-stack-smoke.mjs`：自动创建独立8767服务、独立SQLite与虚构图片，正常浏览器登录、上传、站内切页、原生后台队列、真实HTTP API、表格与人工0提交。模型始终错误99，OCR和模型仅离线替身，网络硬阻断；不连接实际8000，不读取真实密钥。测试结束关闭整个临时服务进程树。[15组真实隔离链路报告](screenshots-v2/browser-scoring-stack-isolated.json)，[虚构材料截图](screenshots-v2/scoring-stack-isolated.png)。

另有原生文字、长扫描件、截图、OCR/AI依赖、快捷审批、RBAC、重复奖项替代、年度封顶和历史冻结等既有回归。所有自动验收均使用临时/模拟数据，不消耗真实云额度。

## 现有数据处理

只用现有识别缓存核验未冻结、未手工修改且来源一致的自动草稿；修改前备份数据库，保留原AI政策信息及系统审计事件。已提交/冻结、人工确认、手工改稿和材料来源不一致的记录不批量覆盖。跳绳材料缺少可可靠绑定的结果时按用户要求保留人工核定；跑步的校级三等奖按奖次制补为1分，不改正式提交状态，不触发新的OCR或AI调用。
