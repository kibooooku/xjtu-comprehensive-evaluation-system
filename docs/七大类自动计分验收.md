# 七大类自动计分与状态一致性验收

## 统一流程

七大类均执行“原件文字与位置 → 本人记录与共同背景 → 规则计算 → 建议应用 → 当前稿与表格 → 提交校验”，不直接接受模型给出的分值。规则版本为 `xjtu-2018-evidence-v2`，分析版本为 `moral-score-v4-scoring-state`。学生可手动填写符合基础数字格式的分值；点击单项或批量提交即确认当前值，包括0。审核资格和年度汇总规则保留。

本人字段只取本人行或单人证明。校级、省级等共同背景来自对应活动正文；同一小项的补充证明须有可对应的活动名称及明确名单/附件关系，不能借学校标志或另一个活动的等级。检查过的空间位置关系不能再用原始OCR乱序文本拼接绕过。

七类只显示具体活动与条目名称、申报分值、备注；只有 `RESEARCH`、`ARTS`、`POST` 显示合并的 `result_label`“获奖/评定等级”和可搜索的“匹配已认定活动”。级别、作者顺序、岗位、任期、工时等仍用于自动计分，不再各设输入框。顶部“查看评分标准”在新标签页打开登录保护的原校PDF。当前交互合同见[申报简化与活动匹配](申报简化与活动匹配.md)。

确认上传后自动进行OCR/本地文字层处理，并在材料处理完成后自动衔接AI。每用户OCR最多同时处理3份文件，AI最多同时分析3个小项，两队列独立，超出排队；点击一键分析及切换页面均不取消OCR。独立网站已验证并发峰值3/3、每项自动排OCR和AI各一次，无手动分析请求；AI满额时OCR继续处理，其结果与事件同步的13项后端并发回归分别验证。

## 七类正常案例与边界

| 大类 | 实际链路中的虚构案例 | 应填分值 | 重点边界 |
| --- | --- | ---: | --- |
| 集体活动 | 本人明确参加2次集体活动 | 0.60 | 次数取证明；不能用模型虚构的次数；突出贡献交人工认定 |
| 思想政治理论学习 | 本人参加普通党团理论培训1次 | 1.00 | 省部级、优秀学员分别取证；未参加、未获优秀不能正向加分 |
| 社会服务 | 本人有效志愿工时16小时 | 0.50 | 工时仅取本人；负数不截成正数；年度志愿子项上限1分 |
| 学术科研及创新创业 | 本人省级二等奖 | 6.00 | 级别、奖次、成果类型独立；论文需本人排序和第一署名单位 |
| 文体竞赛 | 本人校级文体三等奖 | 1.00 | 奖次制保留THIRD，名次制保留PLACE_n，不能把三等奖改成第3名 |
| 学生组织社团任职 | 班长满12月，考评良好 | 1.50 | 本人岗位、任期、考评须对应；不足一年人工核定；不合格合法0分 |
| 奖励分 | 本人获校级精神文明先进个人表彰 | 2.00 | 荣誉不要求必须另有一二三等奖；不能拿别人的表彰或组织级别计分 |

体育证明采用一、二、三等奖表达时，按同赛事级别的前三档提供奖次制填报建议（PRIZE_BAND），不据此推断获奖人的精确名次。资格仍按原流程审核。该口径与体育第4—8名、破纪录等规则分别处理；不再因已经明确的三等奖不属于PLACE_3而保留默认0分。原办法没有独立固定金额的专利指向、项目结项和不足年任职等，必须具体说明人工核定原因。

## 分值状态

API的 `score_resolution` 在当前稿、列表和建议中提供：

- `RULE_APPLIED`：有明确规则计算结果，`value`为两位分值，允许真实0。
- `NEEDS_REVIEW`：缺依据或有冲突，`value=null`；保留稿值只放在 `retained_value`，页面展示“待核定分值”及具体缺项。
- `MANUAL`：学生手动填写/确认，或已冻结分值，正常显示0或非零数，不被新建议覆盖。
- `UNANALYZED`：尚未形成分值；默认数据库0不是已完成计分。

`missing_facts`为 `{code,label}` 数组。页面不把AI调用成功当作填分成功，后台显示“条目已提取，分值待核定”及简短原因。该提示帮助学生核对，不增加独立确认动作。直接提交将当前稿值记录为学生确认并冻结，包括未自动核定时保留的0；批量逐项执行同一规则，部分失败时成功项完成，失败项保留草稿和勾选。

页面普通保存携带 `score_confirmed:true` 和当前 `requested_score`，确认当前填写，保存0亦有效；直接提交不要求预先保存一次已加载且未修改的内容。有未保存修改时，先保存，再携带保存后的版本提交。API只保存标题或无意义空字段而未显式确认分值时，不误标手改。实际改过分值继续使用 `student_modified_score`，同值确认0以独立标记表示。应用未决建议只更新信息，不清除有效的人工0确认。

保存和确认使用表单加载时的 `expected_version`。后台更新了标题、分值、字段或附件时，脏表单不推进版本；旧页返回409并保留用户输入。纯状态或证据刷新、表单依据完全相同时才安全推进版本。材料或计分字段变化后，旧自动分值进入待核定；已手填或冻结分值保持保护。

## 活动匹配与汇总

活动检索在全库按名称、别名和材料正文排序，不再截取前300条；结果显示有效、无效及待认定，AI只能选择返回的合法候选ID。唯一明确全名或别名可提供确定匹配兜底，普通近似和多个明确候选不强行认定。无效的精确匹配不能被较远的有效活动替换；旧停用匹配可只读显示，不能被自动重新应用。

资格判断在搜索、详情、提交和审批中统一使用活动、大类和学年。旧隐藏的届次、赛道、组别不参与当前表单判断；没有可复用通用认定，或通用与历史具体范围认定冲突时，返回 `UNKNOWN` 交辅导员确认。其它四类不检查隐藏的旧活动资格，保存和分析不主动清空其历史字段。

竞赛重复由审查员对照同类完整表格判断，系统不自动替代、拒绝或恢复关联申请。科研、文体竞赛将已通过的小项分值 `SUM` 后按大类封顶；任职 `MAX` 和志愿年度子项封顶保留。同学生/学年/大类的原文件哈希防重复仍生效。

## 现有数据处理

此前的草稿核验修复只使用已有识别缓存，修改前备份数据库，保留原AI政策信息及系统审计事件；已提交/冻结、人工确认、手工改稿和材料来源不一致的记录不批量覆盖。跳绳材料缺少可可靠绑定结果时保留人工核定，跑步校级三等奖按奖次制补为1分的历史修复不改变正式提交状态。本轮简化验收使用临时数据与离线替身，不重新调用真实OCR或AI，不重写已有审核快照。
