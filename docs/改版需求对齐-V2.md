# V2批量申报改版需求对齐

状态：用户已确认Q34及Q35—Q39（“其余都同意”），授权继续修改项目。

## 用户要求

1. 本人参与证据改为单张原页整宽、原页高度四分之一的上下文截图，匹配账户姓名/班级/学号的位置红框标出，显示文件与原件页码。信息分散时优先精确学号所在页，其他位置提供跳转，不拼接原件。
2. 主流程先上传再识别再核对表格；智能识别入口紧邻上传材料。材料在左、信息在右的顺序落实到新表格和证据对照布局。
3. 每个学生、学年、大类只有一份外层申报；里面多个小加分项。主页面点击大类打开上传整理弹窗，确认后显示该大类申报。管理员指定当前统计学年，学生填报不再选择学年。
4. 有效性证据仅活动具体名称、活动时间、印章；不把“特此证明”等套话当证据。缺失时提示人工核对，不虚构截图或活动名。
5. 学生和审查员/辅导员均用小项表格进行比对与逐项审批。已通过小项锁定，仍可新增、修改/删除驳回小项；待审项先单独撤回。历史保留。
6. OCR与AI服务端任务跨页面/刷新持续运行；主页面可一键分析全部未分析项，各类别及小项显示进度。AI名称须包含具体活动。

## Q34：文件与小项

用户原答：
> 一个文件对应一个加分小项，在点击某大类加分入口后弹出窗口要求上传文件时，上传完默认一个文件对应一个加分小项，这个窗口中可以为某一个加分小项补上传文件，这样就实现了一个加分小项可以有多个文件，上传完毕后用户确认即可，这个上传的窗口不要做ocr的识别，等用户确认以后才开始ocr识别，因为ocr比较慢，而且ocr任务也应该能在切换页面时持续运行。

结论：弹窗中每个主文件默认一小项，可给指定小项补充附件；弹窗只整理附件，不调用OCR。确认上传完成后才入后台OCR队列。一份证明的两次广场舞仍合并一项0.6。
