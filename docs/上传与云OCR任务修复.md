# 上传与云OCR任务修复

识别服务继续采用腾讯高精度OCR、SealOCR与DeepSeek；没有安装或替换本地OCR模型。

## 附件与任务

- 单个附件上限200MiB，PDF最多500页；HTTP表单上限205MiB，避免文件符合限制却被旧25MiB请求保护误拒。前端主文件、补充附件及旧上传入口同步提示和校验。
- AI任务记录明确OCR依赖，只在对应OCR成功后执行。重复点击复用任务，不取消、替换、抢跑未完成的OCR；失败OCR需用户明确重试，不由AI暗中重扫。
- OCR材料指纹仅依赖附件、渲染页和来源；改标题、分数或截图不再将OCR误判过期。AI仍使用完整内容快照保护人工稿。
- OCR截图及等待AI的指纹推进放在同一个数据库事务，消除竞争窗口。旧队列可安全兼容。
- Windows进程探活改用只读OpenProcess/GetExitCodeProcess；不再调用可能发出CTRL_C_EVENT的os.kill(pid,0)。
- 运行中的OCR优先展示真实进度，同时提示AI等待OCR；任务栏保留全部活跃任务，不被较新的AI记录遮挡。

## 印章和失败诊断

- 每个文件仅在首页和末页调用查章，单页去重；每个原文件只保留这些页面中的最后一枚，未找到则提示自行寻找与手工框选。超过12页的扫描件仍查首页、末页文字与印章来找有效性证明，中间本人参与信息手工定位。旧持久识别结果应用和可编辑工作稿展示同样遵循策略，手工证据与已批准冻结历史保留。
- DeepSeek网络超时、连接中断、HTTP鉴权/余额/限流、空内容、输出截断、响应JSON及条目JSON错误分别记录安全错误码与中文原因，不暴露凭据或原始材料文本。
- 原有两次“请求失败或返回格式不完整”的历史记录不足以判断具体网络或JSON故障，不将猜测写成结论。已有成功OCR保留。
- 长PDF曾被旧“每小项12页”保护拦住。最终改为逐文件检测文字层：已有文字直接本地读取，超过12页也能供AI分析；无字短文件逐页OCR，长扫描文件仅处理首末页，中间本人参与信息提示手工处理。同项多个短文件不因合计超过12页而整体拒绝。额度不足即停，不自动重跑失败历史或切换服务商。完整规则见[文字层与免费OCR策略](文字层与免费OCR策略.md)。

## 验证

- 实际生成500页PDF可渲染，501页明确拒绝；实际超过旧20/25MiB的合法图片可通过上传及原件下载。
- 200MiB边界、205MiB请求体保护、大小提示均有回归。
- 真实线程与双worker测试验证OCR阻塞时点击批量AI：OCR持续、AI等待、完成后复用已有结果，不重复调用OCR。
- Windows探活测试禁止调用os.kill；权限不足按可能存活处理，避免错误接管任务。
- 字段编辑、删除及来源变更、事务竞争、失败依赖、旧任务队列、每文件最后章、详细错误分类均有专项测试。
