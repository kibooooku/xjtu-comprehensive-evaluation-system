本文件依据《需求对齐记录-grill-me.md》第一部分整理，仅描述逻辑数据流，不构成应用实现。配套可编辑源为 `源文件/dfd.json`。图形布局和导出由统一绘图环节处理。

## 2. 系统边界与外部实体

| 编号 | 外部实体 | 输入系统的数据 | 系统向其提供的数据 |
| --- | --- | --- | --- |
| E1 | 学生用户 | 登录、班级查询、申请字段与原件、截图修订、正式提交／撤回、项目关联确认、公示查询；具有班长身份时提供任免及导出资料，具有审查员身份时提供审核意见 | 身份与脱敏班级信息、AI建议、人工补填提示、申请回执、审核结果、授权原件及成绩、脱敏公示；班长办理结果和Excel |
| E2 | 辅导员 | 登录、查询、审核、活动资格认定与维护、公示设置、导出条件 | 所带班级信息、申请原件与审核资料、成绩、认定及维护结果、历史影响清单、公示办理结果、Excel |
| E3 | 系统管理员 | 登录、账号、班级、组织关系与权限维护资料 | 对应身份结果和维护办理结果，不包含业务证明材料 |
| E4 | 腾讯云OCR | 接收待识别文件页及文字／印章识别类型 | 向系统返回文字、置信度、坐标、印章内容及坐标，或失败／额度耗尽结果 |
| E5 | DeepSeek | 接收识别文本、学生所选大类、适用规则和规范活动候选 | 向系统返回条目细项、建议分值、活动匹配建议或失败结果 |

班长、审查员不是学生之外的互斥基础身份，因此不再各画一个身份实体。在 E1 数据流中标注其职责，具体权限仍由 D1 当前授权与班级范围约束。学生可以同时承担两项职责，但不得审核本人申请。

外部 OCR 和 DeepSeek 服务在系统边界之外。图中的业务请求不包含 API 密钥，凭据配置、云控制台开通和关闭后付费不是这些业务数据流。OCR只使用免费额度，额度耗尽或服务失败转人工补填，不表示转用付费接口。实际额度可能被同账号其他程序消耗，不能从本系统调用记录推导云端必然剩余额度。

## 3. 逻辑数据存储字典

| 编号 | 名称 | 主要内容 | 约束 |
| --- | --- | --- | --- |
| D1 | 账号、角色与组织权限 | 基础身份、附加角色、权限矩阵、学生班级、班长／审查员、辅导员所带班级 | 基础身份互斥；每班一班长、至少两审查员；管理员不能因系统管理身份取得证明材料 |
| D2 | 学年与评分标准 | 可选学年、七类评分细项、70分基准、分类上限、同项目及任职取最高、精度及比较规则 | 源于已确认评价办法；不新增管理员编辑评分规则的需求；不强制固定日期学年边界 |
| D3 | 申请、版本与提交轮次 | 稳定申请标识、当前工作草稿、修订内容、正式提交版本、各轮次状态、项目关系及可计分轮次 | 申请、修订版本和提交轮次分开；正式提交引用稳定版本；工作草稿不等于当前审核状态 |
| D4 | 原文件与关键证据 | 原文件及页信息、材料与版本关联、有效性／本人参与两类截图、页码和坐标来源 | 一申请多原件；每类截图可多张、跨页跨文件；普通公示无原件下载权限 |
| D5 | 活动规范与资格认定 | 名称、ID、别名、有效／无效认定、届次／组别等适用范围 | 活动资格与个人证据、个人分值分离；有效改无效不批量撤销历史申请 |
| D6 | 审核与奖项替代履历 | 审核意见、原因、备注、经办人、版本／轮次引用、替代因果关联、替代前状态、恢复结果及审计 | 历史经办人不受后续任免影响；恢复仅撤销本次替代造成的变化，不覆盖独立人工决定 |
| D7 | 班级学年公示设置 | 班级＋学年、公示状态、操作人及时间 | 按当前待审轮次核验开启门槛；公示禁止正式提交、重提与奖项替代，允许草稿保存 |

D1—D7 是领域信息的逻辑分区，不要求七张物理表。D2 可包含部署时初始化的参考数据，所以业务图中没有常规写入者。D3 的版本内容不在 D6 重复存一份，D6 通过版本／轮次引用连接业务记录；替代前的状态快照属于恢复所需履历。

## 4. 一级进程职责

| 进程 | 数据变换 | 数据边界 |
| --- | --- | --- |
| P1 身份组织与权限管理 | 登录资料转为身份结果；组织／角色资料转为授权关系；班级查询转为相应可见信息 | 管理 D1；为学生隐藏同学学号；维护基础身份、附加职责及班级范围 |
| P2 形成申请草稿与证据 | 原件转为OCR结果，文本与规则转为AI建议，学生修订转为草稿及截图关联 | 七类入口由学生选；学生改内容或分值不强制理由；保存原建议与手动改分标记 |
| P3 受理正式申报与奖项替代恢复 | 草稿与当前规则／资格／公示数据转为受理或拦截；同项目资料转为替代及恢复记录 | 正式提交即替代旧轮次；读取D7当前状态；恢复旧轮次不覆盖新草稿 |
| P4 办理学生与辅导员审核 | 正式版本、证明与审核意见转为审核决定、待后续审核状态及资格认定资料 | 本班非本人审查；四类直接终审、三类按活动资格判断是否需辅导员；退回理由必选 |
| P5 维护活动资格 | 辅导员认定／维护资料转为规范资格记录及历史影响清单 | 个人证据不足不得直接认定活动无效；维护活动库不自动修改既有通过轮次 |
| P6 查询申请证据并计算成绩 | 查询范围及当前业务记录转为授权申请视图和规则成绩 | 明细保留当前已通过条目，计分执行分类封顶、取最高与精度；本人／班长／审查员／辅导员范围不同 |
| P7 办理公示与Excel导出 | 公示设置申请与待审清单转为公示设置；成绩及关键截图转为脱敏展示或15列Excel | 公示只展示通过项；普通同学的名单和截图学号遮挡；导出仅班长和辅导员 |

P4 向 P3 发送的是“轮次、版本、理由、经办人构成的驳回事实”，用于数据恢复，不是“调用下一步”的控制箭头。P3 和 P4 更新的当前轮次成为 P6 后续查询的输入，因此无需在 DFD 中另画“触发重算”信号。

## 5. 主要数据流字典

以下字段表示逻辑内容，不固定接口或数据库列名。

| 数据流 | 内容组成 | 来源→去向 |
| --- | --- | --- |
| 身份及组织维护资料 | 用户标识、基础身份、附加职责、班级／辅导员关系、权限变更 | E1班长／E3→P1；P1→D1 |
| 班级查询结果 | 班级标识、成员姓名、班长／审查员职责；普通同学结果无学号 | P1→E1／E2 |

| OCR请求 | 文件或指定页、文字／印章识别类型，不含API密钥 | P2→E4 |
| OCR结果 | 文字、置信度、文字框、印章内容及位置、页引用；或失败／额度耗尽信息 | E4→P2 |
| 语义评分请求 | 可用识别文本、学生所选大类、评分细项、规范活动及适用范围候选 | P2→E5 |
| AI建议 | 建议条目、类别细项、建议分值、规范活动候选；或失败信息 | E5→P2 |
| 学生确认资料 | 最终草稿字段及分值、匹配修正、两类截图及文件页／坐标、手动改分标记 | E1→P2→D3／D4 |
| 草稿保存结果 | 申请／修订引用、保存结果、待补信息，不产生正式待审轮次 | P2→E1 |
| 正式提交／撤回请求 | 申请标识、修订或提交轮次引用、所选操作 | E1→P3 |
| 关联候选与确认 | 本人同学年可能相同项目的旧轮次、比较信息、学生确认的关联 | P3↔E1 |
| 申报受理结果 | 新轮次引用或拦截原因、被替代旧轮次及计分变化、恢复结果 | P3→E1 |

| 历史影响清单 | 引用被修改活动的历史申请／轮次及当前状态，不包含批量撤销决定 | D3→P5→E2 |
| 替代与恢复履历 | 新旧轮次引用、优先级比较、替代前状态、因果关系、恢复结果或不恢复原因 | P3→D6 |
| 公示设置资料 | 班级、学年、开关目标、经办人，结合当前待审清单核验 | E2→P7→D7 |
| 计分查询与结果 | 授权范围、班级学年；当前已通过明细、按取最高及封顶规则形成的分类合计、70分基准、总分 | E1／E2／P7→P6；P6→查询方 |
| 公示展示资料 | 每生总分、分类合计、通过条目、关键截图、审查员姓名；名单与截图学号遮挡 | P6→P7→E1 |
| Excel汇总 | 班级学年、A:O双层表头；70基准、扣分0、分类多行明细及规则合计、总分、空签字列 | P7→E1班长／E2 |

## 7. 不另制图的审核与公示细化

### 7.1 P4审核

P4.1 汇集审核材料，读取 D1、D3、D4、D5、D6，向当前有权限的审查员或辅导员提供资料。

P4.2 核验学生审查意见对应的身份、本班范围和非本人条件，形成带经办人与版本引用的审查结果。

P4.3 结合所选类别及活动适用范围，把学生审查结果归并为直接通过、驳回或待辅导员审核：集体活动、思政、社会服务、任职直接终审；科研创新、文体竞赛、奖励分仅在适用有效认定存在时免辅导员再次认定。

P4.4 接收辅导员审核资料，区分活动本身无资格与个人证据／分值错误。活动认定资料发送 P5 并接收规范记录；个人错误只影响个人申请。已通过项的后续驳回也由该职责处理。

P4.5 保存轮次审核状态至 D3，意见、原因、经办人及版本引用至 D6，向学生／经办人提供结果。驳回事实发送 P3 处理相关奖项替代恢复。班长／审查员身份变更不重写历史经办人。

这些子职责仅细化一级 P4 的既有边界，不引入新实体或新存储。

### 7.2 P7公示与导出

P7.1 接收辅导员的班级学年设置，读取 D1范围、D3当前待学生或辅导员审核轮次及D7当前设置，形成允许的设置变更或未满足条件的办理结果。草稿和已驳回轮次不阻止开启。

P7.2 根据公示查询／导出条件及D1范围，向P6取得当前规则成绩、通过明细、关键截图及审查员姓名。

P7.3 结合D7开放状态生成同班公示，将名单和关键截图中的学号遮挡，不提供原件，不公开草稿、待审、驳回项。辅导员纠错后的当前数据可再次计算，因此公示不是冻结快照。

P7.4 将授权成绩明细转为双层15列Excel，列出当前已通过条目；分类明细多行展示，分类合计和总分执行封顶／取最高，70基准、扣分0、签字空。不能把取最高或封顶后未增加总分的已通过条目从明细中省略。导出仅向班长或辅导员提供。

P3另行从D7读取公示状态，核验正式提交、重提与替代；这是对持久设置的读取，不是P7向P3发送“禁用按钮”控制流。设置检查和提交、公示开启所依赖的当前数据须在后续设计中保持一致，本逻辑图不指定数据库锁实现。

## 8. UML类与ER映射建议

| DFD信息域 | 建议类／ER实体范围 | 映射要点 |
| --- | --- | --- |
| D1 | User、StudentProfile、CounselorProfile、Class、Role、Permission、RoleAssignment、CounselorClass | 学生附加角色通过授权关系表达，不能设计成基础身份互斥枚举中的独立值；授权受班级范围约束 |
| D2 | AcademicYear、ScoreCategory、ScoringRule | 区分单条建议分、人工确认分和规则汇总；数据模型不要用总分列替代规则 |
| D3 | Application、ApplicationRevision、SubmissionRound | 对应统一命名 applications、application_revisions、submission_rounds；申请稳定标识、工作草稿、正式版本、审核轮次分别表示 |
| D4 | MaterialFile、RevisionMaterial、EvidenceCrop | 一版本可关联多个材料，截图引用原件、页和坐标，并区分有效性／本人参与；存储位置与访问授权分离 |
| D5 | Activity、ActivityAlias、ActivityRecognition／Scope | 规范名称和别名统一；资格认定范围不等同于个人参赛项目去重键 |
| D6 | ReviewRecord、AwardReplacement、AuditEvent | 审核和替代关联提交轮次及正式版本；替代保留因果关联和旧状态，恢复不修改工作草稿 |
| D7 | PublicationSetting | 以班级与学年联合定位；公示状态与可计分轮次独立，不复制一套冻结成绩 |
| P6／P7输出 | ScoreSummary、PublicView、ExportDocument等查询／输出对象 | 可为计算结果或视图，不要求为了DFD输出建立相同名称数据库表 |

上述实体范围供统一UML／ER命名核对，并非另定数据库清单；物理字段及表名以最终统一设计为准。尤其不能把 Application.currentDraftRevision 与恢复目标 SubmissionRound 混为同一对象，也不能把活动资格统一ID当作个人同项目去重键。

## 9. 设计校验清单

- 四张图均无外部实体直接连接存储，也无存储直接连接存储。
- 任一子图跨边界数据在父图有对应来源／去向；细分后内容并集保持一致。
- OCR、DeepSeek的正常与失败结果均有接收进程；人工兜底仍保留原件和正常审核。
- 七类入口来自学生所选；截图具有两类、多张、跨页／文件的表达能力。
- 审核结果引用正式版本和轮次；替代与恢复引用因果关系，不覆盖工作草稿。
- 公示按班级学年，待审清单用于开启门槛，当前设置用于提交限制；公示名单和截图学号脱敏。
- 管理员没有业务原件数据流；班长、审查员作为学生附加职责出现。
- 本设计资料不读取密钥，不调用外部识别服务，不创建应用代码、安装依赖或启动服务。
