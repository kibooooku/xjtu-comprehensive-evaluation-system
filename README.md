# 西交德育分统计管理系统 · V2批量申报

面向班级的德育分申报、材料识别、人工审核、公示与Excel汇总系统。按本项目需求访谈与设计重新实现，使用 **FastAPI + SQLAlchemy + SQLite + 原生JavaScript**，运行时不依赖外部前端CDN。

## 启动

需要 Python 3.12+。Windows 双击根目录 **`启动系统.cmd`**，随后访问 **http://127.0.0.1:8000**。首次启动自动创建37张表、八个演示班级、两个学年及演示账号；重复启动保留数据。由V1升级时自动备份数据库并按大类归组，保留全部原申请、附件、审核轮次和成绩。

手动启动：

```powershell
python -m venv .venv
.venv\Scripts\python.exe -m pip install -r requirements.txt
.venv\Scripts\python.exe run.py
```

Linux/macOS：

```bash
python3 -m venv .venv
.venv/bin/python -m pip install -r requirements.txt
.venv/bin/python run.py
```

默认仅监听本机。端口可在 `.env` 中设置 `PORT`；`instance/` 保存数据库、受保护文件、会话密钥与本地识别预算，均不提交到Git。

## 完整流程

1. 管理员指定当前统计学年，学生填报无需选择学年。历史记录另行查看，只读；审查员可以筛选旧学年处理原待审小项，补交旧年由管理员切回开放。
2. 学生在“我的申报”直接点击七类入口，弹窗中一次整理该类全部PDF/JPG/PNG。默认每个主文件一个小加分项，可为某项补充多个附件；单文件不超过200MB，单个PDF不超过500页。**选文件和整理期间不做OCR，点击确认后才上传并排后台材料处理任务，优先检查已有文字层。**
3. 每个大类只有一份外层申报，小项以表格呈现。材料位于左侧、条目信息位于右侧进行对照。确认后先用代码逐页检测PDF已有文字层，可用时直接提取文字和原页坐标；缺字扫描页才使用腾讯云OCR。材料处理完成自动衔接AI，首次分析自动填入全新小项。每用户最多同时识别3份文件、同时分析3个小项，两个队列独立，超出排队；跨页面/刷新持续，页面显示队列与进度。“一键分析”仍可处理未分析或新增材料，人工稿仅提供建议，不覆盖填写；已有结果、待审和通过项不会被无谓重跑。
4. 本人参与证据为原页整宽、四分之一页高的截图，匹配姓名/学号/班级并画红框；本人奖次或考评不能同框时补充一张结果图，最多两张。证据显示来源文件和原件页码，位于原件之前。有效性证据只取一处完整活动名称、时间、印章，缺失则提示人工核查。AI不得用“集体活动证明”等泛称冒充具体活动。
5. 七类表单只填写具体活动与条目名称、申报分值、备注；仅科研、文体竞赛、任职增加一个“获奖/评定等级”输入和可搜索的“匹配已认定活动”。匹配旁提示“匹配已认定活动，便无需辅导员审批活动有效性”，结果明确区分有效、无效及待认定，允许清除或更正。评分所需的级别、次数、工时、作者顺序等仍由材料分析和规则层处理，不增加表单输入框。
6. 单项和批量点击提交即确认当前填写分值，包括0分；有未保存内容时先保存，再按新版本提交，没有重复确认弹窗或独立确认分值按钮。学生审查员和辅导员在同类完整表格中逐项绿色批准、红色填写理由驳回。已通过小项锁定，但整类仍能新增；待审先单独撤回，驳回项可修改或删除，审核记录保留，曾手动改分会明确标记。
7. 同学生/学年/大类的相同原文件按哈希防重复，改名不能绕过，跨大类可复用证明。是否同一竞赛重复加分由审查员比对，不再自动替代、拒绝或恢复其它申请。科研、文体竞赛、任职三类需要活动资格认定：当前匹配有效时学生初审后可通过，待认定交辅导员，无效活动须更正；其它四类不因历史隐藏的活动匹配阻塞提交。活动资格只按活动、大类、学年判断，历史具体范围冲突交辅导员确认。
8. 70基准、分类封顶、任职取最高和志愿年度子项封顶均按已通过小项计算；科研与文体竞赛按已通过分值累加后执行大类上限。公示前无当前待审小项，公示时禁止正式提交，允许草稿和辅导员撤销已通过项实时更新。
9. 班长或辅导员导出15列双层表头Excel，包括全班无申请同学的70分，扣分0，签字留空。学生、审查员和辅导员页面顶部可在新标签页查看原校评分PDF，接口为登录保护的 `/api/reference/scoring-standard`。

当前表单、活动搜索、提交与人工复核合同见 [申报简化与活动匹配](docs/申报简化与活动匹配.md)。该说明更新早期访谈中的竞赛自动去重和替代规则，原始访谈记录保留作为历史依据。

## 真实AI与OCR配置

凭据仅后端读取，选择以下方式之一：

- 环境变量或本地 `.env`：`DEEPSEEK_API_KEY`、`TENCENTCLOUD_SECRET_ID`、`TENCENTCLOUD_SECRET_KEY`。
- 保持本项目的文件：`secrets/deepseek_api_key.txt`、`secrets/tencent_ocr.env`。腾讯文件兼容 `TENCENT_OCR_SECRET_ID` / `TENCENT_OCR_SECRET_KEY` 等常见命名。

腾讯调用 **GeneralAccurateOCR、SealOCR**，DeepSeek使用可配置的 `DEEPSEEK_MODEL`，默认 `deepseek-flash`。接口状态只返回已配置与本地预算，不返回任何凭据。官方参考见[接口来源](docs/source-references.md)。

只使用腾讯免费资源包：账户侧须关闭后付费。本地每接口默认每月最多1000次尝试，配置 `OCR_GENERAL_MONTHLY_LIMIT`、`OCR_SEAL_MONTHLY_LIMIT` 可调整；该计数包含失败及请求前预留，属于本地调用保护，不能表示腾讯计费量或实际免费余额。系统区分本地上限、腾讯资源包返回、限流、计费状态、鉴权与网络问题，仅明确的资源包耗尽错误才能显示云端资源包不足。相同页面、相同参数复用成功OCR，不自动购买资源或切换服务商。详情见 [调用上限与停止原因](docs/OCR调用上限与停止原因.md)。

`CLOUD_ANALYSIS_ENABLED=false` 可关闭云识别。上传仍允许200MB、PDF最多500页；逐页云文字OCR的单文件上限为12页（`OCR_MAX_ANALYSIS_PAGES`可进一步降低）。PDF已有可用文字层时直接本地提取，不调用文字OCR，超过12页也可供AI分析；长扫描件仍识别首页、末页的文字与印章来提取活动名、时间、盖章，中间的本人参与信息由学生手动定位框选，不阻止同项其他附件处理。腾讯SealOCR对每份文件只检查首页与末页，单页只查一次，未找到时不显示自动章图并提示自行寻找。额度或本地预算不足即停止后续云调用并保留成功结果，不自动切换火山。公示截图须有可靠文字坐标支撑的脱敏版本；未就绪时显示提示，不开放原图。审核端可查看完整原件和私有截图。详见[文字层与免费OCR策略](docs/文字层与免费OCR策略.md)。

OCR/AI任务保存在SQLite中，由服务端工作线程处理；站内切页和普通刷新可继续；退出登录、关闭最后一个本站标签或失联45秒会暂停，重新进入后可明确继续。按用户分别限制OCR文件并发3、AI小项并发3；已完成材料处理的小项自动排入AI，未完成的仍等待OCR，不相互取消。相同输入复用任务和成功OCR缓存；人工变更、删除、冻结或学年切换后不覆盖新稿。服务进程意外中断时恢复队列，已完成页复用缓存；云接口失败不自动重试，由用户选择重试或手填。

火山 AI MediaKit 标准版保留为文字识别备选；[独立实测指引](docs/火山MediaKit开通与测试.md)与脚本不参与正式任务，也不会在腾讯额度不足时自动调用。专用 Key 放在 `secrets/volcengine_mediakit.env`，既存实测报告只留本地 `instance/mediakit-test/`。

## 权限、历史与数据

采用“角色—资源操作—数据范围”矩阵，逐条授权相交后求并，再施加强制规则：基础身份互斥、目标班级范围、禁止自审、管理员不得读取材料、每班一名班长及至少两名审查员、公示提交锁。前端隐藏菜单与后端鉴权同时存在；直接请求API也受同样约束。

已提交内容冻结，重填生成修订，审核与事件绑定原轮次；历史快照和处理记录保留，对照核对统一在大类页面展示。SQLite写操作使用 `BEGIN IMMEDIATE`，公示检查、提交及审查在事务中完成。密码scrypt哈希，HttpOnly/SameSite会话、CSRF、来源检查和密码更改后旧会话失效；文件不通过静态目录公开。

没有将用户原始示例证明、原始学生汇总表、密钥或数据库提交到仓库。评分规则见[规则说明](docs/scoring-rules.md)；当前交互与审核合同见[申报简化与活动匹配](docs/申报简化与活动匹配.md)，原始[需求访谈](需求对齐记录-grill-me.md)保留历史记录。

## 验收与开发

```powershell
python -m pip install -r requirements-dev.txt
python -m pytest -q
node --check app/static/app.js
node --check app/static/workspace.js
```

自动测试使用临时数据库与虚构材料，云适配使用受控替身，**不会消耗云额度**。新版真实服务小样可显式运行 `python scripts/smoke_v2_cloud.py --cloud`，使用隔离测试数据库，每类OCR最多一次、DeepSeek一次，验证后台自动填表与新截图；同数据复验复用成功缓存。

本次简化新增活动全库检索、七类字段显隐、直接提交及并发保护回归。六份浏览器报告共83项：简化表单19、真实隔离链路19、统一对照12、单项提交6、OCR队列13、稳定性14，错误均为0。独立网站实测OCR文件及AI小项并发峰值各3，上传后每项自动排OCR、AI各一次，AI满额时OCR仍继续，无手动分析请求。文字OCR、印章和模型分别调用9次离线替身，外网请求、真实云调用、真实业务写入均为0。后台任务及材料相关回归82项全部通过，含13项事件同步并发检查；另有23项活动匹配链路检查。报告入口见 [V2验收记录](docs/v2/acceptance.md)。

浏览器验收脚本为 `scripts/browser-v2-smoke.mjs`，需在 `.tools/browser` 安装Playwright并有Chrome。验收前用 `CLOUD_ANALYSIS_ENABLED=false` 启动服务，脚本也会检查此开关；否则上传确认会触发真实OCR。所有浏览器材料是虚构测试数据。

本地旧数据升级前的备份位于`instance/backups/`，可用 `python scripts/verify_migration.py` 只读核对原申请和审核轮次保留情况。
